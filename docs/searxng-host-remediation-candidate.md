## Bounded read-only preflight already prepared

`scripts/searxng-remediation-preflight.py` is a fixed-object, host-operator-only **read-only** probe. It opens every source path component with `O_NOFOLLOW` and directory descriptors, requires the fixed file/cache device+inode and settings owner/mode, bounds the settings read to 1 MiB, checks file stability before/after, and emits only a settings SHA-256, conservative JSON-format state and empty-cache/identity metadata. It separately verifies exact daemon/container/image, stopped original, the two existing mounts and requested loopback binding. It classifies environment differences by key internally: image defaults and only an explicit `FORCE_OWNERSHIP=false` override are directly recreatable; network/config/proxy overrides are dangerous and other overrides require review. It emits counts/classes, never environment values or arbitrary key names. Its only Docker operations are `info` and fixed-object `inspect`; no `start`, `create`, `pull`, file mutation or service change. `sourceSnapshot=PASS` means only that selected bytes were safely read. The overall preflight is `FAIL` when source/cache ancestors are user-replaceable, even when the snapshot succeeds; insufficient candidate facts produce `UNKNOWN`. `candidateInputsSufficient` only means that selected pre-publication facts are available; it is not trust, approval or runtime readiness. The source is still user-controlled; an exact digest must be bound to a later, separately approved transaction.

This preflight has **not** been run as root or against the Docker daemon by Work Execution. It is not a publication script and needs separate exact-hash operator approval before host execution.
