## Known blockers and limitations

- OMP cannot yet be executed locally because Bun >=1.4 is absent. No OMP numeric result is inferred.
- A new Git worktree does not contain ignored managed LSP binaries. Baseline tests use the verified runtime in the stable installation via `PI_OVERDRIVE_LSP_RUNTIME`; the Ultra worktree has its lockfile-pinned Node LSP dependencies materialized.
- OMP comparisons are source/architecture-only until an isolated executable reference can be provided without changing either product's data.
- Tool-schema numbers use a bounded non-executing registry inside real Pi; production counts vary with installed tools, while the live selection and denial behavior is the code path under test.
- Pi 0.85.1 has no native OMP-style extended/discoverable namespace; `/tools` provides name/tier discovery without placing rare schemas in the prompt.
- Sentinel is intentionally explicit rather than a background watchdog. It sees only the bounded task supplied to `/sentinel`, not the transcript or workspace, and permits exactly one call per session. A selected Oracle route with missing price metadata is blocked rather than silently rerouted.
- ResourceFS now supports immutable repository/memory/artifact/local-Git/conflict resources. The local Git runner remains Linux-x64 and repository-root-only. GitHub `pr://`/`issue://` are intentionally absent until authenticated read-only access can be proven without changing credentials; remote mutation and publishing remain unavailable.
- SmartRead deliberately supports source/text only; archive, database, document, and image parsing remain outside its reviewed surface. Cold LSP startup adds latency even though it materially reduces context.
- Artifact Store Phase 5 supports UTF-8 text only. Binary images/browser captures remain deferred to the hardened browser phase, and critical-diagnostic preservation can intentionally make a pathological preview exceed its nominal character target rather than discard an error.
- Context estimates deliberately follow Pi's conservative four-character approximation plus a 4,096-token safety reserve; they are not provider billing tokens. Critical diagnostics can force a BLOCKED result rather than be discarded.
- Pi 0.85.1 exposes no safe in-flight API for changing the active target after final context assembly. The Context Governor therefore blocks an irreducible payload and requires explicit compaction/handoff or an already-policy-compatible target instead of silently changing routing.
- Edit Engine V2 owns exact and bounded single-file AST transactions, JSON pre-validation, and Phase 9 pre/post managed diagnostics. Phase 17 selects only among those already-governed contracts with one fallback; multi-file structural/rename/file-move transactions remain intentionally absent.
- Model Harness Profiles currently contain only evidence-backed direct OpenAI/Pi declarations plus a restrictive generic profile. OmniRoute routes retain `UNKNOWN` harness capabilities until authoritative local metadata or reproducible evidence exists; no remote probing or adaptive learning was introduced.
- Phase 9 validates the edited file within its bound project and does not grant server-originated workspace mutation. Genuinely unsupported file types skip by explicit policy; a configured managed server that is absent/unpinned or a runtime failure blocks the guarded transaction. Multi-file rename/import/file-move control remains deferred until it can be atomic and rollback-safe.
- The tracked AST binary digest is intentionally Linux-x64-specific, matching the existing package platform contract. First use hashes the 52.4 MB binary, so the measured cold AST path includes that one-time integrity cost; subsequent uses revalidate filesystem identity before using the cache.
- Edit snapshots/transactions are deliberately memory-only and expire after 30 minutes. Applied receipts are bounded per session and metadata-only but do not yet have a package-owned time-retention command.
- Phase 10 is intentionally Linux-x64/GDB-only. Debug sessions are memory-only and single-session; attach, core files, expression/function evaluation, memory operations, watchpoints, disassembly, remote targets, arbitrary adapter commands, and other adapters remain unavailable. Source breakpoints can remain pending until symbols load.
- Phase 11 is intentionally pinned to the reviewed Linux-x64 Python/Node/TypeScript/prlimit files. Host runtime upgrades require a reviewed policy update. Eval state is memory-only; JavaScript is synchronous; TypeScript is transpile-only; and top-level await, timers, async host APIs, dynamic/package imports, rich display/images, tool/resource bridges, project/user files, and filesystem persistence remain unavailable. Kernel output is capped at 256 KiB before Artifact Store processing.
- Phase 12 deliberately recognizes only three conservative controller-owned intent classes and only after complete structured arguments exist. It does not predict every unsafe trajectory and never replaces safety, safe execution, sandboxing, or Tool Governor enforcement. Pi 0.85.1's blocked pre-hook lifecycle requires the narrow safety integration documented in the implementation note; a failed reservation or persistence path simply omits the correction while the governing block remains effective.
- Phase 13 does not continuously watch, capture transcripts, steer, mutate, execute tools, spawn, retry, or replace Oracle/reviewers/Council. Its USD ceiling relies on registered price metadata and therefore fails closed when a selected route has unknown pricing; provider-reported thinking may remain honestly marked unreported when the adapter does not expose it.
- Phase 14 is session-local and projects only secure-workflow role attempts. It does not discover arbitrary direct subagent jobs, search historical runs, expose role content, or provide steer/cancel/revive/spawn/message controls. Running duration and usage remain unavailable until authoritative lifecycle/receipt evidence exists. The same-process event bus is inside the installed package trust boundary; the Hub adds no authority if another executable extension is compromised.
- Phase 15 is deliberately one task and non-persistent. It does not split work into independently steerable workers, retain worker transcripts, or provide send/steer/revive/kill controls; the existing isolated Worker/correction sequence remains the sole implementation path. A task-aware read-only MCP proxy or bounded web tool is retained only when the Tool Governor already enabled it for the exact task.
- Phase 16 remains Linux/Git-specific and requires a clean source repository. Reflink is unavailable on this filesystem and overlay was intentionally not mounted. Node lacks a complete descriptor-relative `openat2`/`renameat2` lifecycle, so a hostile same-UID directory-replacement race cannot be claimed impossible; private roots, canonical checks, atomic records, Git registration, and post-cleanup checks reduce and expose that risk.
- Phase 19 is deliberately proposal-only and requires explicit path/hunk ownership. It does not infer commit groups, persist source content, stage, commit, amend, reset, branch, publish, or authorize a later mutation. A future apply path would require a separate human-approved controller design; stale proposals are never silently regenerated.
- Phase 20 is deliberately project-only and parses a strict compatibility subset. Scoped rules are omitted when no safe task file path is present; multiline YAML, brace/extglob patterns, executable conditions/TTSR, user-home and environment-selected rules are rejected. Pi core still loads root `AGENTS.md` natively, so Ultra can add a lower-authority boundary around imported rules but cannot replace that loader with its descriptor-relative reader.
- Phase 21 implements only one local text ACP session/root and has no client MCP, filesystem, terminal, model/thinking switching, session reload, multi-client control, or persistent approval. Pi and trusted extensions retain their existing host permissions; ACP is an interface, not a new sandbox. The bridge journal is transport metadata, not workflow success evidence. The isolated benchmark excludes the unavailable ignored MCP runtime through an exact package filter while keeping security/context hooks; a full installed package still requires its pinned bootstrap runtime. Startup stderr is hashed/classified without raw preview because persisting it could leak secrets.
