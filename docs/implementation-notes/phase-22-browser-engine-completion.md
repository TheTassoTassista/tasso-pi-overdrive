# Phase 22: confined autonomous Browser Engine

Phase 22 is complete at functional commit `5701876`. The ordinary interactive `pi-agent-browser-native@0.6.6` installation is unchanged. In managed autonomous allocations its `agent_browser` tool is blocked before execution; Tester instead receives `browser_engine`. Task Governor still requires explicit browser intent and Tool Governor keeps the browser high-risk conditional. Outside an allocation the new tool cannot start. The original narrow action validator remains authoritative for the allocated session, profile, port, commands, selectors, timeouts, and fixed capture request. JavaScript eval, external/file initial navigation, CDP attach, auth/cookies/storage, upload/download, arbitrary output paths, alternate sessions/profiles, and broad modes remain denied.

`lib/browser-engine.mjs` starts lazily on the first valid `open`, verifies the exact installed `agent-browser@0.36.0` and Chromium 152.0.7977.82 executable SHA-256 pins, and owns one Bubblewrap process group and one allocation/session. `runtime/browser/runner.py` stays alive across open/snapshot/fill/click/wait/get/screenshot/close. Bubblewrap uses `--unshare-all --clearenv --die-with-parent`: a private network namespace has only loopback, the pinned browser/Chromium and runner are read-only mounted, the profile is the exact private allocation directory, and `/home` is a private tmpfs. The controller copies one bounded, single-link `index.html` through descriptors into private state; the runner serves only `/` inside the namespace on the allocation's port. The staging pathname is removed after mount readiness. No host loopback service is mounted or reachable. Runner handshake and every action attest the same network namespace; the controller also pins the Chromium PID/start-time identity throughout the session. Cancellation, command timeout, runner/Chromium crash, abnormal exit, and exact close tear down the owned process group/namespace without name-based killing.

Screenshots are written first to namespace-private `/tmp`, opened `O_NOFOLLOW`, bounded to 4 MiB, and transferred only to the controller. The controller verifies SHA-256, PNG signature/chunk boundaries/CRCs/dimensions, and stores one owner-only, single-link, content-addressed PNG in the allocation's private runtime state. The model receives bounded metadata/digest, not bytes or a host path. Allocation cleanup deletes the image/profile; this is a browser-owned binary artifact layer, **not** a generic binary Artifact Store extension or a durable image-view API. Controlled downloads and credentialed browsing are **deferred for safety**. There is no raw browser eval or external CDP authority.

The real Pi 0.85.1 smoke (`npm run smoke:browser`) used only the deterministic local provider and pinned browser stack. It proved forbidden eval and native allocated browser calls were blocked before profile materialization; ten allowed calls used one runner, one Chromium process and one network namespace. The local page's `fetch` and image attempted a host-side sentinel that was confirmed reachable from the host (control request 200) but received zero requests from Chromium; the page reported `OVERDRIVE_NETWORK_BLOCKED`. Snapshot, fill, click, wait, DOM read, CRC-valid private PNG, exact close, runner/process/worktree/port/allocation/temp cleanup all passed. Focused tests cover lazy startup, wrong owner, policy denial, runner crash, exact/double close, timeout, Chromium crash, missing fixture/partial startup, missing Bubblewrap executable, stale allocation, and malformed PNG. The Phase 22 authoritative gate passed **459/459**, syntax, installed-Pi TypeScript, package/secret validation; role, guardrail and spawn-budget smokes passed. The later Phase 23 gate passed 460/460. No paid or external provider calls occurred; extra cost was €0.

Limits: this is a **local unauthenticated single-file UI fixture engine**, not general web browsing. The private runtime profile and screenshot are still ordinary same-UID files; a hostile same-UID process can race or inspect owner files, so this is not a same-UID adversary boundary. The fixture server is a thread owned by the runner, not a separate process; independent thread-death injection has not been tested. The browser stack and SHA pins are Linux-host specific and must be reviewed on upgrades. Browser-owned PNGs disappear with allocation cleanup and are not yet image-consumable through ResourceFS. A one-off 457/458 full-suite result occurred during development; two immediate suite reruns and the final 459/459 full gate passed, with no reproducible failing case identified. Per maintenance policy this is recorded, not patched speculatively. Do not treat this browser boundary as authority to automate the ambient desktop in Phase 23.
