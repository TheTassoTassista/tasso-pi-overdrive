# Phase 35 — optional bounded Watchdog

The Watchdog is an opt-in, deterministic local advisor. It is **off at session start** and exposes only `/watchdog status`, `/watchdog on`, and `/watchdog off`. Enabling it does not start a timer, model, process, agent, tool, or provider call. It runs synchronously on the existing secure-workflow checkpoint event, using only controller-owned aggregate metadata. It is not a second controller or a semantic code reviewer.

The delta contains run and Task Policy digests, coarse task classification, workflow phase/round, verification statuses, and counts of non-Council role failures, failed verification, correction, and blocking findings. It contains no task text, transcript, paths, diff bytes, receipts, tool arguments, Council content, or secrets. The strict schema caps input at 768 characters. Council-phase observations are skipped; Council failures do not count as role failures. Task Policy rejects direct tiny edits and ordinary low-risk tasks even after opt-in. The policy file is fixed and no-follow opened; model/tool input cannot raise its bounds.

Triggers are a pass-to-fail verification regression, repeated verification/role failures, or repeated correction with blocking findings. One isolated failure is silent. A relevant-state digest suppresses duplicate reviews; reviews have a 30-second cooldown and a limit of two per task (one under Token Saver, with a higher failure threshold). A new run resets the budget. Advice is one of NIT/CONCERN/BLOCKER with a validated 600-character maximum. This implementation generates fixed, evidence-count-only text; provider/model calls are exactly zero, with no unverified zero-cost route. The output validator rejects extra fields, oversized or secret-bearing text, and command/authority language. Watchdog failures are caught and cannot fail the main workflow.

The production extension publishes a task-local advisory message without triggering another Pi turn. A run-digest-bound, revalidated in-memory advice value also reaches the authoritative workflow controller. The controller may include it as **untrusted data only in an already-required correction Worker handoff**. It cannot cause a correction, turn a failing verification into PASS, change reviewer/Council/Judge decisions, alter routing or retry policy, or grant any tool or mutation authority. The value is consumed once and cleared on workflow completion. No Watchdog advice is automatically committed to Second Brain. Traces contain only allowlisted metadata (status, reason code, digest, duration, context size, zero model-call/provider label, severity and count); never the advice or observed state.

`benchmarks/overdrive-vs-omp/watchdog.mjs` compares disabled and enabled arms for a successful workflow, repeated failures, unchanged observations, and a post-PASS regression. It invokes the actual `runEnforcedWorkflow` state machine using deterministic local delegates and no external provider. Saved result: all three workflows end PASS in both arms, with identical delegate counts (7/22/26); the successful case triggers no review, repeated failure triggers two bounded reviews with eight duplicate suppressions, and regression triggers one review. One existing correction Worker in each failing scenario receives the advice. The maximum actual delta was 474 characters; no model, external provider, or tool call was added. These are fixture delegations, **not** billable model calls, and do not establish general token savings.

`benchmarks/overdrive-vs-omp/watchdog-pi.mjs` starts real Pi 0.85.1 with isolated settings and a deterministic offline fixture. It proves command registration, default-off and tiny-task skips, two structured advice messages without a new agent turn, duplicate suppression, malformed-event fail-soft handling, metadata privacy and temporary cleanup. It emits the production observation event from a fixture; it does **not** run an authenticated end-to-end secure workflow. OMP execution and paid/model comparison remain NOT_RUN. Total added monetary cost is €0.

Known limits: this local advisor sees only the listed aggregate checkpoint fields, not diff size, detailed tool errors, security transitions, or explicit Director requests. It cannot infer code correctness and never substitutes for verification/reviewers. The event bus shares Pi's extension host; a separately installed hostile extension with host authority is outside this feature's trust boundary (Phase 38). Installed stable Pi configuration is unchanged; this feature exists in the experimental Expansion worktree until separately promoted.
