# Phase 23: hardened computer use — deferred for safety

Assessment on the local Hyprland 0.56.2 / Wayland session, after Phase 22 completion. No desktop screenshot, click, key, type, scroll, focus change, or model/provider call was performed. `hyprctl version` and the desktop portal D-Bus introspection were read-only checks.

The active portal declares Screenshot, ScreenCast, and InputCapture, but no RemoteDesktop interface. `grim` and `slurp` are installed; `wtype` and `ydotool` are not. A direct `grim` capture can include unrelated applications, credentials, and notifications; a `hyprctl` dispatch or generic input injector would act on the ambient host desktop. The available interfaces do not establish an end-to-end per-action approval, exact target binding, protected-window exclusion, evidence redaction, or a reviewed input adapter. The isolated Phase 22 browser controls its own private page and namespace; it cannot be repurposed as desktop authority.

Decision: **do not register a `computer_use` schema or any screenshot/input tool**. Screenshot/inspect/click/type/key/scroll are all deferred, rather than adding a broad host capability or a token-consuming but unprovable consent layer. Existing Tool Governor classification treats unreviewed desktop tool names as `unclassified-denied`; a regression now checks they remain hidden even when task text explicitly requests desktop actions. Autonomous roles continue to load no desktop-control extension. Ordinary Pi, authentication, routing, Second Brain, Council/Judge, and browser isolation remain unchanged. Cost and external provider calls: zero.

Reopen only for a concrete task with an adapter that proves user-visible approval for each action, exact window/region identity at execution time, non-credentialed screenshot review before model delivery, bounded private image lifecycle, no arbitrary shell/JS/filesystem bridge, focus/target revalidation before input, and fail-closed cancellation/cleanup. A future portal-based screenshot-only slice must be independently tested and should not imply click/type authorization. Until then Phase 23 is **DEFERRED FOR SAFETY**, not a claimed computer-use implementation.
