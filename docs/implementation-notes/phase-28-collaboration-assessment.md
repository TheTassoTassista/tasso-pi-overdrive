# Phase 28: secure collaboration assessment — deferred for safety

The Phase 24 decision was revisited against the pinned OMP reference commit `a1b3b83a7fb8460445f2f5995a6aa56047bd44c7` and the current Overdrive controller. No relay, listener, guest, link, session export, network request, model call, or provider call was started.

The pinned OMP collaboration documentation describes live replication of the full session and tool cards. Its view-only link still grants the historical transcript, and its control link permits prompts, interrupts, subagent control, and interactive responses. OMP's host remains authoritative, but the link itself is a bearer credential and joining creates a persistent guest replica. Those behaviors are reference features, **not** accepted Overdrive defaults.

Overdrive's local Agent Hub is a metadata-only projection, while the ACP bridge serves one local editor session under exact per-call approval. Neither provides authenticated guest identity, role-scoped session projection, guest-copy retention, or a host approval broker for remote actions. The current request does not identify a guest, the data that may be shared, an approved relay endpoint, or whether an observer may see even bounded session metadata. Adding a loopback listener or issuing a strong token would not by itself resolve those authorization choices.

Decision: **DEFERRED FOR SAFETY**. No code/schema/listener/autostart/guest link/transcript replication was added. The safe minimum future design remains one existing authoritative workflow controller plus a separately authenticated, session-bound, expiring and revocable guest identity. Default guest rights should be OBSERVER over an explicit redacted projection with no back-transcript; COMMENTER suggestions and OPERATOR actions require separate host decisions, and every mutating action must pass the existing controller and host approval. Council-private outputs, hidden reasoning, credentials, prompts, tool contents, and private artifacts must not be exposed by default. Transport logs should remain metadata-only, guest copies bounded and deletable, and any listener loopback-only until a separate remote opt-in review. An unguessable URL alone is not authentication.

Reopen for a named opt-in collaboration workflow and a specified disclosure/retention boundary. Until then, preserving the existing local-only configuration is the correct result, not a claim that secure collaboration is implemented. Phase 28 introduced zero model/provider calls and €0 extra monetary cost.
