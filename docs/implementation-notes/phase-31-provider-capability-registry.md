# Phase 31 — Provider Capability Registry (bounded completion)

The registry composes Pi's local model declarations, the existing owner-only callability cache, existing Model Harness Profiles, and an optional local OpenRouter catalog snapshot. It never fetches metadata, probes a model, owns an adapter, or authorizes a route. `/models --capabilities` defaults to a short summary; provider/exact-model/callable filters are bounded to 50 records, and `--json` exposes field-level evidence. Catalog presence is separate from Pi registration, authentication, and runtime callability.

Every capability carries its own state, source, observed time, and freshness. Runtime receipt evidence has a seven-day freshness window; catalog metadata has a 24-hour window. Conflicts are explicit and deterministic. Context and output limits take the smaller known bound even when an old source only lowers capacity; ordinary fields use VERIFIED > BENCHMARKED > DECLARED > CACHED > STALE > UNKNOWN. The Context Governor consumes only a non-increasing limit for its already-selected model. Model routing, quality, Council/Judge, retry, spawn budget, and profile edit contracts are untouched.

The local catalog reader opens one regular, non-symlink, owner-controlled, at-most-2-MiB JSON file and whitelists only capability fields. The host cache observed on 2026-09-24 contains 445 OpenRouter IDs but was fetched on 2026-09-13, so its evidence is **STALE**. The cache is incomplete as an OmniRoute provider catalog; absence is not a rejection. Its prices omit an explicit currency/unit contract, so the registry publishes those prices as UNKNOWN. Likewise, a Pi adapter's default zero/zero cost is not proof of a free route, and rate limits remain UNKNOWN. A positive declared price is never called zero-cost, but without explicit units it is not a verified billing quote. No credential, description, raw prompt, provider response, or secret-bearing raw catalog field is serialized into the registry.

Focused evidence: 13 registry/catalog tests PASS; offline real-Pi routing smoke 13/13 PASS with zero inference calls; real-Pi deterministic Context Governor benchmark PASS for both fit and pre-provider block; local metadata benchmark resolves 1,000 representative four-model registries (including stale/conflicting/catalog-only cases) in 277.608 ms total, 0.2776 ms mean, with 2 conflicts, 19 UNKNOWN fields, 0 external calls and 0 routing mutations. This timing measures only local fixture resolution, not provider latency or full Pi startup. The authoritative gate with the documented LSP runtime passes 498/498 tests, syntax, installed-Pi TypeScript, package and secret validation. Bare `npm test` without that selector still lacks the ignored Rust/Go LSP binaries in this worktree and fails the two documented LSP tests; this is not hidden by the registry.

Remaining limits: no fresh or complete authoritative OmniRoute catalog; no rate-limit source; catalog prices remain UNKNOWN; runtime callability freshness is informational rather than a silent route-policy change. No paid or external model/provider calls were made.
