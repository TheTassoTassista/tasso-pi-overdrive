# Phase 21: bounded ACP editor bridge

The bridge implements the ACP v1 JSON-RPC/stdio subset needed for one editor project session. It is a transport adapter: official Pi 0.85.1 remains the execution engine and the existing Overdrive package remains the policy, routing, tool and workflow owner. The bridge is opt-in through `npm run editor:bridge -- --cwd /absolute/project`; ordinary Pi startup does not run it.

The bridge accepts `initialize`, `authenticate`, `session/new`, `session/prompt`, `session/cancel`, `session/close`, and an idempotent `session/set_mode` for the sole `overdrive` mode. It rejects unknown methods, client MCP servers, extra directories, root aliases/traversal/symlinks, later sessions, parallel prompts, slash commands and direct route/model/thinking/terminal/filesystem controls. It does not persist Pi sessions or change provider/auth files. Pi is launched with fixed `--offline --approve --no-session --mode rpc` flags and one explicit `--extension` for the editor approval hook. The hook is absent from `package.json`'s explicit extension manifest, so it has one loader. The `--approve` trust choice is limited to this explicit local bridge launch and the caller's exact canonical root.

For a relevant tool call, the hook computes a canonical argument digest and asks the bridge to request `allow_once` or `reject_once`. The bridge requires the matching active Pi tool-call ID, tool name, operation kind and argument digest. A decision is bound to that one session, request and operation. Replayed, stale, mismatched, cancelled and late decisions fail closed. The ACP approval does not replace Task Governor, Tool Governor, safety hooks, safe execution, transactional editing, verification or secure-workflow evidence.

The owner-only transport journal is not a second workflow authority. It records exact allowlisted metadata: digests, statuses, route, token counters and cost. It cannot contain prompts, paths, arguments, tool output or credential values. Existing secure-workflow role/evidence receipts remain authoritative for autonomous runs; the existing trace-retention mechanism prunes old bridge journals. Pi stderr is classified and hashed in a bounded startup failure receipt, without retaining raw text. Editor-visible content streams over ACP but is not persisted by the bridge.

The local benchmark uses a real Pi process and the real package hooks. Only the MCP proxy is excluded through Pi's supported package filter because this isolated worktree lacks its ignored installed runtime; MCP is unrelated to the write path. The benchmark uses a deterministic local provider and an explicit fixture route, checks the file before granting permission, then verifies exactly one `write`, one `allow_once`, two local provider turns, route receipts, metadata privacy, unchanged auth, and process/temp cleanup. The bridge itself never selects the fixture route. OMP was inspected at pinned commit `4267074ac91456866e95ed8de0b6353388f08502` but not executed because Bun >=1.4 is unavailable.

Limitations: ACP is intentionally a narrow subset, limited to one project/session and text prompts. It does not expose client files, MCP, terminal, session reload, model selection, or persistent grants. The bridge inherits Pi's package/runtime availability and policy. The metadata-only journal is a transport diagnostic, not proof that a secure workflow passed; consult the existing workflow receipts for that claim.
