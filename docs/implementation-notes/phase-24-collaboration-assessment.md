# Phase 24: collaboration relay — deferred for safety

Assessed after Phase 23 against the pinned OMP collaboration documentation and the current Ultra/Pi tool surface. This assessment used local source and policy checks only: no relay, listener, guest, browser share, network request, model call, or provider call was started.

OMP's collaboration feature can replicate a whole session, including back-transcript and tool cards. A control link also lets a guest submit prompts, interrupt the host, control subagents, and answer interactive requests. The host executes the agent and tools. Even a view-only link discloses historical session content. Therefore a relay is not merely an alternate UI: it introduces a new principal with read or execution influence, a bearer-secret distribution channel, retention decisions, and a network service. The existing ACP bridge is a single local editor session with per-call mutation approval; it is not an authenticated multi-client collaboration broker. The Agent Hub is a local metadata-only projection, not a guest authority source.

There is no concrete opt-in guest workflow or approved read/write privilege split for this installation. There is also no reviewed guest authentication and revocation mechanism, host-visible per-action approval, transcript redaction policy, or bounded guest-copy retention. A loopback-only relay would still disclose session history to another process and would not solve those properties. Reusing the ACP bridge or Agent Hub as if they supplied them would silently widen authority.

Decision: **DEFERRED FOR SAFETY**. Do not add a collaboration tool/schema, listener, autostart, guest link, transcript replication, prompt/interrupt route, or remote subagent control. A Tool Governor regression checks that plausible unreviewed collaboration controls remain unavailable even when task text explicitly asks for sharing and when manual enablement is attempted. This regression does not claim to sandbox an arbitrary third-party extension loaded outside the reviewed package.

Reopen only for a named opt-in use case with an explicit data classification, authenticated guest identity, separate read/control grants, revocation, host approval for every mutating action, strict mapping into the existing controller (not a second workflow), metadata-only transport logs, bounded encrypted retention and deletion, deterministic disconnect/replay handling, and adversarial local tests. Do not transmit past session content by default. Until that contract exists, preserving the local-only boundary has higher value than feature parity. Extra monetary cost and external/provider calls: zero.
