## Execution model

- **KNOWN:** `scripts/phi-check.mjs` sorts `phi-*.test.mjs` and invokes one Node test runner with `--test-concurrency=1` for `--owned-validation`. The Windows and Ubuntu matrix jobs use separate machines; steps inside each job are sequential. The Windows dedicated mixed-journal step precedes the main suite, and the clean-room clone comes after it (`.github/workflows/phi-foundation.yml`). In `tests/phi-mixed-journal.test.mjs`, each V5 case uses synchronous `spawnSync`; no asynchronous native fixture is launched by that file. Thus those test-file processes and their V5 fixtures cannot overlap through this runner's normal path.
- **KNOWN:** A fixture deliberately overlaps its parent with a publisher until it kills and waits for that child; `concurrent-terminal` deliberately starts two contenders *within the same transaction*. The clone's aggregate suite and descendants run inside one unnamed native Job (`platform/windows/native/OwnedProcess.cs`); main-suite `spawnSync` helpers do not acquire a fixture-specific Job. A GitHub runner's own Job membership is not equivalent to a Phi-owned per-fixture Job.
- **KNOWN:** Numeric TAP completion order is the reporter's observation order, not proof of start times, absence of buffered delivery, or actual execution duration. `scripts/phi-runtime-reporter.mjs` explicitly records observed completion gaps with this caveat. Therefore a green ordered TAP stream alone cannot establish fixture non-overlap or isolate test 206/209's historic causes.
- **POSSIBLE, not observed:** A helper that survives an unexpected controller death in the unowned main-suite path could overlap later work. No such residual is proved by the existing failed runs; the clone Job's zero-residual proof does not retroactively prove the main suite's process count.
