# Pi Overdrive Ultra

## Design contract

Ultra adds an OMP-class tool plane beneath the existing Overdrive control plane. It does not replace Pi, authentication, model routes, Council/Judge, workflow receipts, sandboxing, or Second Brain.

```text
task → Task Governor → task policy
                     ├─ Model Governor (existing routes/callability)
                     ├─ Context Governor (SmartRead + memory + artifacts)
                     └─ Tool Governor (small task-specific surface)
                                      ↓
                           existing secure workflow
                                      ↓
            transactional edit / AST / LSP / DAP / eval
                                      ↓
                    safe execution + Bubblewrap + receipts
```

The architecture is lazy and fail-soft. Optional parsers, debugger adapters, eval kernels, browser processes, and Sentinel sessions start only when the task policy requires them. Their absence must produce a bounded degraded result, never prevent ordinary Pi startup.

## Frozen invariants

- Official Pi 0.85.1 installation and existing authentication are not modified by development.
- Existing provider identities, role assignments, fallback order, thinking policy, Council composition, Judge sequencing, and retry categories remain authoritative.
- Council has three independent read-only members. Members receive the same initial evidence but never another member's output; Judge runs only after three valid results.
- Autonomous concurrency is 3, depth is 1, correction rounds are 2, and the derived session spawn budget is 42.
- Worker stays sandboxed in the workflow worktree; Tester stays non-mutating.
- Second Brain remains OpenViking + Hindsight + ACE + Memory Router + Shared Memory Pack + Obsidian, with local CPU embeddings.
- No feature may turn secrets, raw prompts, file bodies, or provider output into trace metadata.
- A disabled or unavailable optional feature must leave the basic `read`/`edit`/`write` path usable.

## Implemented control plane

Phase 1 adds the versioned deterministic Task Governor. It composes the existing Token Governor, Memory Router, and preset/quality policies into one digest-bound Task Policy. A small direct string change resolves to one Worker, four capability intents (`read`, `edit`, `lsp`, `verify`), no Planner, memory, debugger, browser, reviewer, or Council. A race under load resolves to a focused debugging policy with Planner, project memory, SmartRead/LSP intent, debug/eval/Sentinel intent, Worker, deterministic verification, and correctness review.

The Task Policy contains metadata and limits, never the raw task. The secure workflow persists it and validates its digest on resume. `/task-policy [--json] TASK` previews the decision locally without a model call.

Phase 2 adds the versioned deterministic Tool Governor. Immediately before each model turn it resolves the Task Policy against Pi's live tool registry and installs only the required schemas. `read` is always essential; FFF/AST search, edit/write, LSP, memory, verification, and the enforced workflow are conditional; web/browser require matching explicit task intent; `safe_exec` and MCP are hidden/on-demand; raw shell, raw subagent, and file removal are controller-only. Unknown tools fail closed. Explicit Pi CLI tool flags remain authoritative, and `/tools` exposes a schema-free inventory plus deliberate session-local enable/disable/auto controls.

AST mutation uses a separate semantic `structural-edit` capability. A tool name or simple string replacement cannot activate it; a structural transformation over syntactic nodes can. Search-only work prefers FFF over redundant built-ins and cannot receive mutation tools. Tool Policy validation reconstructs the deterministic decision from the bound Task Policy and recorded live registry, so a recomputed digest cannot bless a semantically forged surface. The same Task Policy makes top-level Second Brain construction truly lazy for small direct edits.

Phase 3 adds a clean-room ResourceFS core with two deliberately narrow, immutable schemes: `repo://root/<relative-path>` for bounded workspace read/literal search and `memory://root/<encoded-query>` for access through the existing Memory Router and Shared Memory Pack controller. Each scheme declares capabilities, trust, and immutability. The strict hierarchical parser rejects traversal, separator encoding, credentials, ports, query/fragment ambiguity, controls, and unknown schemes. Repository access reuses workspace/secret policy and walks path components through held `O_NOFOLLOW` directory descriptors, then revalidates inode identity; symlinks, hard links, `.git`, `node_modules`, binary reads, and oversized reads fail closed.

ResourceFS currently exposes no `WRITE`, `MUTATE`, or `EXECUTE` operation. A future risky handler cannot register without a controller-owned authorization callback. One conditional `resource_fs` schema appears only for explicit supported URIs, while `/resources` reports the catalog without a model call. Explicit `memory://` access suppresses duplicate automatic memory injection. Tool output marks resource bodies as untrusted data, and traces contain only scheme/operation/status/size/trust plus a URI digest—never the URI, query, path, or body.

Phase 4 adds deterministic SmartRead. A large supported source read through Pi's ordinary `read` tool is replaced before model context with file structure, imports/includes, declarations, signatures, exact ranges, reopen suggestions, and an omission marker. Small files remain verbatim. Explicit `auto`, `raw`, `smart`, and `range` modes are available through the conditional `smart_read` tool; raw and range modes are hard-bounded.

SmartRead uses the Task Policy's preset/context budget and task text only for local ranking. ResourceFS owns canonical path enforcement, the pinned read-only LSP enriches document symbols when available, and deterministic multi-language parsing/line fallback keeps the feature fail-soft without a model call. Metadata traces contain only bounded counts, sizes, status, and digests. FFF remains the locator and `semantic_nav` remains the deeper definition/reference path; SmartRead does not duplicate either system.

Phase 5 adds one content-addressed Artifact Store for large UTF-8 tool results. Output above the configured threshold becomes a deterministic untrusted preview plus manifest metadata and `artifact://<sha256>`. Sanitized content is private, immutable, session/workspace scoped, task-attributed, quota-bound, deduplicated, and reopenable only through bounded ResourceFS line ranges or literal search. The middleware preserves non-text blocks, prior details, usage, and Pi error state; storage failure degrades to a bounded redacted inline preview.

The store has no model-callable schema of its own. Explicit artifact URIs activate the existing conditional `resource_fs` tool, and `/artifacts` reports metadata without inference. Secrets, complete private keys, terminal controls, malformed manifests, cross-session IDs, symlinks, hard links, permissive files, and digest mismatches fail closed. Artifact retention uses its own seven-day manifest lifecycle and stale-orphan cleanup; it shares neither files nor deletion rules with metadata traces. Binary/browser artifacts remain deferred to the browser phase.

Phase 6 adds one fail-closed Context Fit Gate immediately before every normal provider request. It accounts for the system prompt, active tool schemas, conversation, Shared Memory Pack/Second Brain context, artifact previews, agent summaries, tool output, reserved output, the target model window, Pi's reported usage/window when available, and a fixed safety reserve. If needed it applies only evidence-preserving reductions in the mandated order: redundant artifacts, generic tool output, historical raw reads through a SmartRead envelope, older Second Brain packs, then conversation prefix already represented by a genuine Pi compaction summary.

Every fresh subagent role loads the gate. A matching PASS proof is attested again in `before_provider_request`; an error, stale proof, or remaining overflow calls `ctx.abort()` rather than relying on a swallowed hook exception. The direct `/handoff` completion path has an equivalent pre-call check, while `/context-fit` inspects the current target locally. The latest user request and current evidence are never silently truncated. Pi 0.85.1 has no safe in-flight route-switch API at this boundary, so an irreducible payload is blocked for explicit compaction/handoff or a policy-compatible target; routing and callability remain unchanged.

Phase 7 adds Edit Engine V2 as one conditional `transactional_edit` schema. Successful exact reads create expiring, session-local `hash-replace-v1` snapshots containing content/path digests and the line ranges actually observed. Preview requires unique disjoint anchors entirely inside those ranges, verifies the current target, permits only bounded unique relocation with exact adjacent context, and returns `READY`, `SAFE_RECOVERY`, or a fail-closed error without mutation.

Apply reopens through held no-follow descriptors, rechecks the file and canonical parent identity, stages and fsyncs complete bytes beside the target, atomically renames, fsyncs the directory, and publishes a private mode-0400 metadata receipt. Receipt failure rolls back only if the installed inode and digest are still engine-owned; concurrent external work is preserved as a rollback conflict. JSON syntax is checked before preview succeeds. Pi's exact editor stays as a separately governed fallback, and model-specific contract selection remains Phase 17. `/edit-engine` and traces expose only counters/digests/status.

Phase 8 adds one conditional `transactional_ast_edit` schema layered on the same transaction engine. Preview requires an exact-read snapshot, one ast-grep pattern/rewrite pair, and an explicit expected match count. The pinned `ast-grep 0.45.3` binary runs lazily against a private copy of the snapshot rather than the live target; its compact UTF-8 byte ranges and replacements are strictly validated before an `ast-grep-v1` transaction can exist. Changed counts, unseen/overlapping ranges, malformed output, contract confusion, and any live-source change fail closed.

Apply uses the Phase 7 descriptor-anchored atomic path and private metadata receipt. Tool Policy selects this contract only for semantic structural-edit intent, hides the plugin rewrite when the transactional tool is present, and restores that plugin only as a governed fallback. Search-only tasks, Tester, reviewers, and Council gain no mutation permission. `/ast-edit` validates and reports the lazy binary locally; trace records contain only counts/status and pattern/rewrite digests.

Phase 9 adds an internal LSP write guard to both transactional editors without another model-facing schema. Baseline diagnostics run against the transaction's actual current bytes; candidate diagnostics run against the exact intended bytes through an in-memory LSP overlay while the repository remains read-only. A multiplicity-aware semantic comparison blocks new configured severities without treating unchanged existing errors as new. Language, backend, and project identities are bound across the checks.

After the descriptor-anchored atomic rename, the guard forces fresh diagnostics from the real filesystem. Any new error, runtime/backend/project divergence, or diagnostic mismatch triggers conflict-safe rollback before a success receipt can exist. The immutable receipt records only bounded counts and digests. Unsupported languages fail soft by explicit policy; a missing/unpinned configured server or runtime failure fails the guarded mutation path closed. `workspace/applyEdit` remains denied, server lifecycle/isolation stay unchanged, `/lsp-write` is a zero-model local status command, and routing/roles/permissions are untouched.

Phase 10 adds one conditional, clean-room `debug_engine` schema for a lazy single GDB DAP session. The engine exposes only launch, source breakpoint, continue, step-over, stack, scope, variable, bounded output, status, and termination. It exposes no attach, arbitrary adapter/request/command, expression or function evaluation, memory operations, or multi-session control. The Linux-x64 policy pins the exact GDB path, version, arguments, and SHA-256 and attests the binary on first use.

The adapter and debuggee run together inside the existing networkless Bubblewrap sandbox with a cleared environment and read-only workspace. Workspace programs and sources are descriptor-checked against secret, link, size, and replacement attacks, including a second program check before configuration resumes execution. DAP frames, messages, output, requests, variables, timeouts, idle lifetime, and shutdown are bounded; malformed protocol, reverse requests, timeouts, or session shutdown deterministically destroy the process group. Artifact Store externalization handles large debug output, while traces retain metadata and digests only. `/debug-engine` inspects the lazy status with zero model calls and no adapter process.

Phase 11 adds two conditional schemas, `persistent_python` and `persistent_javascript`, backed by one session-local kernel per language. JavaScript and TypeScript share the JavaScript kernel. Exact Linux-x64 Python and Node paths, versions, arguments, and SHA-256 digests are pinned and attested before first use. Kernels are lazy, sequential, bounded by code/frame/output/value/memory/time limits, and destroyed on timeout, crash, reset, idle expiry, explicit termination, or Pi shutdown; the next execution starts with clean state.

Each kernel receives only a private runner copy mounted read-only as `/workspace`, the read-only system runtime, a private temporary filesystem, a cleared environment, and a new network namespace through the existing Bubblewrap launcher. The project workspace and user home are not mounted. There is no ResourceFS, tool, shell, or subprocess bridge. Python builtins/imports and the JavaScript VM global are additionally restricted as defense in depth, but the operating-system sandbox is the security boundary. Repository evidence must first be obtained with normal governed tools and passed explicitly as data.

Results preserve bounded stdout, stderr, and the final value. Long lines are chunked before Artifact Store middleware so oversized results externalize without dropping Pi error state. Traces contain only language/action/status/isolation/count/timing metadata, never code, output, values, prompts, paths, or secrets. `/eval-engine` reports policy and session counters without starting a kernel or making a model call. Worker alone receives the governed eval tools; Tester, reviewers, Council, and all other roles retain their existing permissions.

Phase 12 adds a controller-owned StreamGuard with no model-facing schema. It observes incremental tool arguments, buffers at most 16 KiB per call, confirms only complete structured arguments, and reserves at most one correction per turn and eight per session with a two-turn rule cooldown. Reservations are persisted before use and contain only rule/tool/session-local digests, counters, timestamps, and status—never the arguments, command, path, prompt, tool output, or reminder body.

StreamGuard is not an execution barrier. Existing `safety.ts`, `safe_exec`, Tool Governor, path controls, and sandboxes still decide whether a tool runs. Pi 0.85.1 does not invoke the post-tool-result hook for a pre-hook block, so the safety hook consumes a matching session/tool reservation only after it has independently decided to block, persists delivery, and places the concise `ERROR [STREAMGUARD]` correction in that same immediate blocked result. The next normal provider step sees it with no abort, retry, timer, queued prompt, runtime, network access, or extra model call. Session replacement, wrong tool identity, failed receipt persistence, replay, terminal state, and shutdown drop the correction fail-closed. `/stream-guard` reports bounded local counters without inference.

Phase 13 adds Sentinel as an explicit, one-shot, read-only second opinion for tasks the deterministic Task Governor already classifies as hard or critical debugging work. `/sentinel TASK` reuses the exact selected Oracle route; it does not add a model role, change provider/model/thinking policy, start Council, enter the secure workflow, or expose a tool schema. The completion receives only the bounded task and `tools: []`. A metadata-only reservation is persisted before the call and permanently consumes the one-invocation session budget, including across resume.

Sentinel has no edit, write, shell, eval, browser, web, subagent, delegation, or steering authority. It uses no automatic retry, enforces a 45-second timeout, conservative 4,096/768 input/output limits, and a USD 0.05 worst-case price ceiling from advertised model rates. Strict JSON advice is rejected on tool calls, extra fields, secrets, control characters, route/thinking mismatch, truncation, or budget excess. Valid advice is inserted without starting another agent turn and is visibly wrapped as untrusted data that cannot override routing, workflow, Council, verification, safety, or sandbox policy. `/sentinel status` makes no model call.

Phase 14 adds a metadata-first Agent Hub as an ephemeral read-only projection, not a second workflow registry. `/agents` consumes only the controller's durable journal, controller-owned role reservation, correlated subagent-start event, and immutable terminal role receipt. Exact schemas carry lifecycle identity, route identity, limits, counts, timestamps, digests, and receipt-normalized usage; prompts, transcripts, reasoning, paths, tool input/output, file content, credentials, and Council-member output are structurally absent. Running and missing accounting remains `UNAVAILABLE` until the same durable receipt source used by workflow verification exists.

The Hub cannot steer, message, cancel, revive, spawn, select models, alter budgets, call tools, or make model/provider requests. It validates the fixed concurrency 3, depth 1, correction-round 2, and spawn-budget 42 envelope, correlates lifecycle by controller identity rather than display text or timing, and fails soft without becoming a workflow dependency. Council/Judge sequencing, routing, retries, role permissions, sandboxing, and durable state remain owned by their existing controllers.

Phase 15 adds optional one-task Director Mode. `/director TASK` first resolves the existing deterministic Task Policy with zero model calls and activates only for non-trivial mutating work where the current Planner, reviewer, or Council policy already proves delegation value. Read-only work and direct small edits stay on their normal small path. The command submits the exact task once, adds a turn-local Director instruction, and exits automatically when the agent is settled.

While active, the primary agent is restricted to bounded read, planning support, `secure_coding_workflow`, and `verification_gate`; repository mutation remains exclusively inside the existing isolated Worker/correction path. Tool selection is clamped after Tool Governor and a second allowlist barrier rejects any late or manually resurfaced edit, write, shell, `safe_exec`, raw-subagent, browser-mutation, destructive, or unknown call. Director Mode adds no worker registry, steering protocol, model route, retry, worktree, receipt, state machine, or provider call of its own. The secure workflow and Agent Hub remain the implementation authority and projection respectively.

Phase 16 hardens that workflow's existing isolation rather than adding another backend. Every new allocation is explicitly `git-worktree-v2`; canonical private roots cannot overlap the source repository or each other, symlink components are denied, and owner-only single-link records are opened with `O_NOFOLLOW`. Resume, release, recovery, lookup, and cleanup reconstruct the exact expected worktree, branch, state, browser profile, port reservation, database, and schema identity before acting. The existing PID + boot ID + process-start tuple remains the live ownership proof.

The measured local capability probe kept the native Git worktree: it excluded ignored private state and completed full cleanup, while reflink was unavailable on this filesystem and overlay was intentionally not mounted. Copy/mount backends would add ignored-state exposure or privileged teardown plus a second capture/apply lifecycle without replacing Bubblewrap, so neither is selectable. Worker correction rounds continue in the same isolated worktree; no role, controller, routing, retry, Council, or tool schema changed.

## Planned subsystems

The implementation order is deliberate: Task Governor and Tool Governor landed before new large schemas. ResourceFS provides typed, policy-checked repository, memory, and artifact URIs; SmartRead selects bounded source views; Artifact Store externalizes large text outputs; Context Governor proves the assembled payload fits before provider entry; Edit Engine V2 makes exact replacement read-bound and transactional; the AST adapter converts structural matches into that same atomic contract; LSP-on-write validates the exact candidate plus the final filesystem state before receipt; DAP provides one isolated lazy debugging runtime; and persistent eval provides two isolated lazy computation runtimes without project or tool authority. StreamGuard can correct an in-flight trajectory without duplicate injections. Sentinel is read-only and policy-gated. Agent Hub consumes metadata and authoritative receipts. Director Mode is an explicit state machine, never an approval bypass.

Git/GitHub resources, commit planning, imported rule formats, ACP, browser expansion, computer use, collaboration and native fast paths follow only after their security and overhead are measured. Computer use and collaboration may be intentionally deferred when the safe design is not better than omission. Native code is justified only by profiling.

## Evidence policy

Every phase has a focused test, local benchmark when relevant, local commit, and an entry in `docs/overdrive-ultra-progress.md`. Cross-product claims are scoped to the category actually measured. A missing OMP runtime or missing comparable metric is `NOT RUN`, not a win.

No OMP source has been copied through Phase 16. Any later reuse must retain MIT attribution and be listed with its source path and commit; clean-room implementation remains preferred.
