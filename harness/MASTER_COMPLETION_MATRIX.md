## Current work item

G2 targeted replay reproduction on the existing workflow journal showed that a stale interrupted run could be selected even after a newer completed run for the same task and repository, because only interrupted journals were considered and selection used the latest checkpoint time. The selection now requires the newest *started* run to be interrupted and receipt-free; explicit IDs, tied/invalid timestamps, and unreadable journals fail closed. Focused evidence/recovery tests 6/6, TypeScript, package validation, syntax and diff check pass. This does not prove persistent pi-subagents background-task retirement after parent restart; its earlier `processTerminal=pending` observation remains unresolved. G3 has a delegated deterministic Worker fixture but no matched direct-main fixture with equivalent task/model/tool budget, so correctness, latency and token advantage cannot be claimed; no new agents or orchestration change. Next independent task: a bounded matched offline G3 comparison, or another queue item if the installed runtime cannot expose comparable usage; Pi/Undici release remains blocked.

Follow-up G1 child evidence on installed Pi 1.5.0/subagents 0.84.0: an actual foreground Worker with deterministic local provider ran four turns. The child registered `debug_engine`, `persistent_javascript`, and `write`; automatic selection activated debug/eval but not raw write. Invoked eval was refused by the Worker authority (`PHI_WORKER_TOOL_DENIED`), a protected breakpoint was refused, and raw write was tool-not-found. No fixture file changed, no external request occurred, and the revocation control also passed. This proves the exercised denial path and explains why G1 is not complete; do not loosen Worker authority merely to make eval pass.
